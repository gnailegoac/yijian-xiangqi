# CONTRACT-NOTES — readings chosen in wave 0 (F0)

This file lists every place where the build contract (`SPEC.md`, same folder) was ambiguous or contradicted itself while the wave 0 foundation was built, with the section it concerns and the reading that the frozen F0 files now embody. It does not change the contract; it records how it was read, so that every later package applies the same reading instead of choosing again. "§" numbers are contract sections; file paths are relative to the repo root.

Items 1–64 were raised by the five F0 builders or by the integrator and were checked against the contract text by the integrator. Items 65–79 (section G) were raised by independent checkers who compared the finished foundation with the contract, and were decided by the F0 finisher after re-reading the contract at each reference. The rule for every decision: where the contract disagrees with itself, the typedefs of §3 and the signatures of §4 stand, and the prose that needs something they do not offer is read so that it works without a new name.

Items marked **OPEN** could not be fully settled inside F0. **They are all settled now: section I (items 80–86, "Owner decisions after wave 0") is the final word on every OPEN item, and where section I differs from an earlier item, section I wins.** Nothing is left for packages to negotiate between themselves.

An index by package is at the end.

## A. Rules that apply to every area

1. **§2 import rule vs. the type references of §3.10, §3.11, §4.18, §4.28.** The rule governs runtime imports only: `import` / `export … from` statements, dynamic `import()`, and `new URL(…, import.meta.url)`. Types cross areas through JSDoc `@import { X } from '…'` tags and `import('…')` type expressions inside comments (the contract itself does this in `Session` and `CoachPort.brief`). The wave 0 tree has exactly two runtime imports (`notation.js` re-exports `moveToNotation` from `engine.js`; `search-worker.js` imports `brain.js`). The build's import crawl (§4.30.2, T1) must strip comments before it looks for imports.
2. **§2 import table omits `src/config.js` and the four `types.js` files.** Read as "no runtime import at all" for these files.
3. **§3 preamble vs. the code blocks of §4: where a named typedef lives.** The typedefs of §3 are in the four `types.js` files. A typedef printed inside a §4 module block lives in that module: `ParseResult` in `core/notation.js`; `SearchControl`, `Searcher` in `core/search.js`; `JobControl`, `Brain` in `core/brain.js`; `MoveBook` in `coach/book.js`; `GameMemory` in `coach/memory.js`; `TurnReport` in `coach/brief.js`; `Timeouts`, `CoachClient` in `coach/client.js`; `Session` in `game/session.js`; `Store` in `game/store.js`; `Budgets` in `game/policy.js`; `Director` in `game/director.js`; `AppConfig` in `src/config.js`; `CoachConfig` in `server/config.js`. **Exception, UI:** the controller typedefs of §4.28.1–4.28.7 (`BoardView`, `Pt`, `BurstKind`, `BannerKind`, `Fx`, `SfxName`, `AudioEngine`, `Speech`, `Buddy`, `Bubble`, `StreamText`, `ChatPanel`, `Hud`) are all in the frozen `src/ui/types.js`, because packages X1–X8 reference each other's controllers; the UI module files import them from `./types.js` and do not re-export them.
4. **Shapes the contract describes but never names** (the result of `createTasks`, `createRivalView`, `computeLayout`, `createSigner`, `memoryStore`; a `PLAN` row; the store's `teacher` dependency). No name was invented. Refer to them as `ReturnType<typeof createTasks>` and so on, `typeof PLAN.fast`, `Parameters<typeof createStore>[0]['teacher']`.
5. **§15 wave 0 ("stub bodies throw") vs. constants the contract gives literally.** A constant cannot be a throwing stub, so these are final already: `PLAN` (§4.8.1); `PROTOCOL_VERSION`, `LIMITS`, `CAPS`, `DISPLAY_CAP_FACTOR` (§4.10); the lexicon tables (§4.11); `SYSTEM_PROMPT`, `TOOLS` (§8.1, §8.2); `mockStats`; `KEYS`, `SCHEMA` (§4.20); `STR` (§4.23); `RIVAL_LINES`, `RIVAL_NAME`, `RIVAL_TITLE`, `CHILD_TITLE` (§4.22); `TXT` (§4.28.8); `VIEW_W … Y0` (§10.1); the constants and one-line helpers of `position.js` (A2.6); `MATE`, `WIN`; `START_FEN`, `NO_CAPTURE_DRAW_PLIES`, `MAX_PLIES`. Functions are throwing stubs even where the contract prints their body (`shouldSpeakOpp`, `announceChance`, `voiceHeld`, `softCheck` in §4.22; the six geometry functions in §10.1; `computeLayout` in §12.2): the owner transcribes the printed body.
6. **§3.5, §3.7, §3.10: several `@property` tags on one line.** Kept verbatim; TypeScript 7.0.2 parses each as its own property (checked for all 316 properties of `core/types.js`).
