# 弈间 · 中国象棋

一个教 9～12 岁孩子下中国象棋的网页游戏，给已经会走子、想下得更好的孩子。

孩子是「小主公」，对面是会看着孩子的水平让着教的对手「司马懿」，身边有军师「诸葛亮」：

- 每一步都可以先在棋盘上**试走**，军师看一眼给一句点评；觉得不好就「换一步」，想好了再「确定落子」。
- 想不出来可以拆**三个锦囊**：第一个只提一个问题，第二个指出该看哪一块，第三个才说出着法。
- 可以点按钮问军师（这步好不好？对方会怎么应？有更好的吗？为什么？），接通大模型时还可以自己打字问。
- 司马懿不是一味让棋：他按孩子最近的表现调整强弱，留出孩子找得到的机会；孩子占了大优势，他会把棋引向孩子能亲手将死的局面。
- 一盘下完，军师只说一件做得好的事、一个下一盘的小目标。

目标只有一个：让孩子爱上下棋。

这份说明前半部分写给家长（不用看代码）；后半部分「给动手改代码的人」写给开发者。

---

## 一、最快的开始：在这台电脑上玩

1. 装好 [Node.js](https://nodejs.org/)，版本 **22.3 或更高**（推荐 24）。
2. 第一次使用，在项目文件夹里打开终端，运行一次：

   ```powershell
   npm ci
   ```

3. 启动，两种方式任选其一：
   - **双击项目文件夹里的 `启动象棋.cmd`**。
   - 或者在终端里运行 `npm start`。

4. 用浏览器打开窗口里打印的「本机地址」，默认是 http://127.0.0.1:5173 。

**启动的那个窗口要一直开着**，关掉它游戏就停了。不能直接双击 `index.html`：游戏的算棋部分必须通过 `http://` 地址才能运行。

两种启动方式的区别：`npm start` 只有这台电脑自己能打开；双击 `启动象棋.cmd`（等于 `npm start -- --host 0.0.0.0`）同时让家里的 iPad 也能打开，见下一节。

## 二、在 iPad 上玩（iPad 和电脑连同一个 Wi-Fi）

电脑当服务器，iPad 用 Safari 打开电脑上的地址。

1. 在电脑上双击 `启动象棋.cmd`，或者运行：

   ```powershell
   npm start -- --host 0.0.0.0
   ```

   第一次启动时 Windows 防火墙会问是否允许 Node.js 联网，请允许「专用网络」。

2. 窗口里会打印可以用的地址和军师的状态，例如：

   ```text
   弈间已启动
     本机地址：http://127.0.0.1:5173
     局域网地址：http://192.168.1.50:5173
     局域网地址：http://MY-PC:5173
     军师模式：live（大模型军师已接通）
     在 iPad 上用同一个地址打开，并“添加到主屏幕”
     请一直用同一个地址（电脑名打得开就用电脑名，否则在路由器里给电脑固定 IP）：存档跟着地址走，换地址前先在设置里“导出存档”
   ```

3. 在 iPad 的 Safari 里打开其中一个「局域网地址」，也就是 `http://<电脑的局域网地址>:5173`。注意是 `http`，不是 `https`。

4. 打开后点 Safari 的分享按钮，选 **「添加到主屏幕」**。以后从主屏幕的图标进入：全屏、没有地址栏，而且 Safari 不会因为七天没访问就清掉这个网站的存档。

### 请一直用同一个地址

存档（下到一半的棋局、孩子的兵法境界、设置）保存在 iPad 的浏览器里，并且**只属于打开它的那个地址**。换一个地址打开（比如电脑的 IP 变了），就像换了一个新网站，看不到原来的存档。所以：

- 优先用电脑名的地址（上面例子里的 `http://MY-PC:5173`；在 iPad 上常常要写成 `http://MY-PC.local:5173`），只要 iPad 上打得开，它就不会变。
- 电脑名打不开时，在路由器里给这台电脑固定一个 IP（DHCP 保留地址），然后一直用这个 IP。
- **换地址之前先导出存档**：菜单 → 设置 → 存档 → 「导出存档」，会下载一个 `弈间存档-日期.json`。用新地址第一次打开时，开始画面上有「导入存档」；之后在设置里也能导入。清理浏览器数据之前同样先导出。

## 三、没有 key 也能玩什么：全部

军师的话有两种来源：

- **本地军师**：游戏自己根据棋盘上算出来的事实造句，不联网，不花钱。
- **大模型军师**：电脑上的「军师服务」把同样的事实交给大模型来说，说得更活，还能回答孩子自己打字提的问题。需要一把大模型网关的 key（见下一节）。

没有 key 时，游戏**全部功能照常**：试走点评、三个锦囊、按钮提问、终局小结、会调整强弱的司马懿、存档、三套主题、音效，都在。唯一的区别是没有打字提问的输入框，军师的句子是固定句式。孩子不会看到任何「离线」字样；菜单 → 设置里写着军师现在的状态和原因（例如「服务器没有配置密钥（COACH_API_KEY）」）。

## 四、接上大模型军师：`.env.local`

军师服务是 `npm start` 自带的一个小代理（地址以 `/api` 开头）：浏览器只把棋局事实发给它，由它带着 key 去问大模型网关，再把回答一段一段传回来。key 只存在于电脑上这个进程的内存里，不会发给浏览器，也不会打印到窗口里。

1. 把 `.env.example` 复制一份，改名为 `.env.local`。
2. 填上 `COACH_BASE_URL`（网关地址，例如 `https://gateway.example.com/v1`）和 `COACH_API_KEY`（网关的 key）。两项都要填，只填 key 不填地址等于没配。
3. 重新启动。窗口里「军师模式」显示 `live` 就接通了。

**安全须知**

- **永远不要提交 `.env.local`**，也不要发给别人。它已经写在 `.gitignore` 里。
- **请在网关后台给这把 key 设一个消费上限。**
- 默认只有本机和家里局域网（内网地址）的设备能用军师服务，并且有限速：每个地址每分钟 30 次、每天 600 次，全部加起来每天 2000 次。局域网里即使有人乱用，能得到的也只是这位军师按固定提示词说出的象棋讲解，数量不超过上面的上限。
- 孩子打字问军师的话会发给大模型网关来生成回答（游戏里的输入框旁有提示：不要写姓名、电话、学校）。军师服务不保存、不记录对话内容；没有账号，没有 cookie。不想让孩子打字提问，可以在菜单 → 设置里关掉「可以打字问军师」，或者在 `.env.local` 里写 `COACH_FREE_TEXT=0`。

### `.env.local` 里可以写的变量

除了前两项都可以不写（`.env.example` 里有同一份清单）：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `COACH_BASE_URL` | 无 | OpenAI 兼容网关的地址，例如 `https://gateway.example.com/v1` |
| `COACH_API_KEY` | 无 | 网关的 key。没有它、又没开模拟模式时，军师模式是 `off`（`no_key`） |
| `COACH_MODEL` | `openai/openai/gpt-6-sol` | 每一种讲解用的模型 |
| `COACH_QUICK_MODEL` | 同 `COACH_MODEL` | 开局和「对手走了一步」这两种一句话讲解用的模型 |
| `COACH_REASONING_EFFORT` | `low` | 推理强度；留空或填 `none` 表示不向网关传这个参数 |
| `COACH_MAX_TOKENS` / `COACH_MAX_TOKENS_OVER` | `1200` / `1600` | 一次回答 / 终局小结最多生成的 token 数 |
| `COACH_UPSTREAM_TIMEOUT_MS` | `60000` | 等网关回答的最长时间（毫秒） |
| `COACH_MOCK` / `COACH_MOCK_CHUNK_MS` | `0` / `15` | 模拟模式开关 / 模拟回复每一小段之间的间隔（毫秒） |
| `COACH_ALLOWED_HOSTS` | 空 | 额外允许用来访问 `/api` 的**主机名**（逗号分隔，必须完全一致，不写端口；写成 `名字:端口` 则只放行那个端口）。`localhost`、电脑名（含 `电脑名.local`）、本机和内网的 IP 地址本来就允许，不用填。见下面「用别的名字打开时军师不说话」 |
| `COACH_ALLOWED_ORIGINS` | 空 | 额外允许的**其他网站**来源（逗号分隔，必须完全一致）。页面和 `/api` 是同一个地址时不用填，家里的 iPad 就是这种情况 |
| `COACH_ALLOW_NO_ORIGIN` | `0` | 填 `1` 时接受不带 `Origin` 头的 POST（curl、测试脚本） |
| `COACH_PUBLIC` | `0` | 填 `1` 时接受本机和内网地址以外的访问者 |
| `COACH_RATE_BURST` / `COACH_RATE_PER_MIN` | `20` / `30` | 每个 IP 的限速（可突发次数 / 每分钟补充次数） |
| `COACH_IP_DAILY` / `COACH_GLOBAL_DAILY` | `600` / `2000` | 每天（UTC）的请求上限：每个 IP / 全部合计 |
| `COACH_TRUST_PROXY` | `0` | 填 `1` 时，限速按 `x-forwarded-for` 的第一段来认访问者（只有前面架了反向代理才需要） |
| `COACH_SIGNING_KEY` | 自动推导 | 给军师回复签名用的密钥，至少 32 个字符 |
| `COACH_FREE_TEXT` | `1` | 填 `0` 时不接受孩子自己打字提问，只保留按钮提问 |

取值的写法：

- 开关类的变量**只有恰好写 `1` 才算开**（`true`、`yes` 都不算）。`COACH_FREE_TEXT` 相反：不写、留空或写 `1` 是开，写别的都是关。
- 数字要写正整数；写 `0` 或写错时用默认值。
- `COACH_SIGNING_KEY` 不足 32 个字符时会被忽略（改用自动推导的）。
- `COACH_REASONING_EFFORT=`（等号后面留空）的意思是「不传这个参数」。如果只是不想改它，请把这一行删掉或者保持行首的 `#`，不要留一个空的等号。
- 启动时读取项目文件夹里的 `.env` 和 `.env.local`，同名变量以 `.env.local` 为准；启动命令所在的环境里已经设置的同名变量优先于这两个文件。变量的值不会被打印出来。

### 确认军师真的接通了

1. 看启动窗口：「军师模式：live（大模型军师已接通）」。
2. 浏览器打开 `http://127.0.0.1:5173/api/health`，应当看到 `"ok":true,"mode":"live"` 和模型的名字。这一步不会访问大模型，不花钱。
3. 真正问一次大模型（会产生一次很小的费用）。在项目文件夹里另开一个终端：

   ```powershell
   curl.exe -N -H "content-type: application/json" -H "origin: http://127.0.0.1:5173" --data-binary "@tests/fixtures/coach/try.json" http://127.0.0.1:5173/api/coach
   ```

   （在 Windows PowerShell 里要写 `curl.exe`，单写 `curl` 是另一个命令。）应当依次看到：一行 `event: open`，数据里是 `"mode":"live"`；若干行 `event: delta`，数据里是一小段一小段的中文；最后一行 `event: done`，里面是整句话和 token 用量。

   如果去掉 `-H "origin: ..."`，回答是 403：军师服务只回答从它自己的页面发来的请求。测试脚本确实需要不带 `Origin` 时，在 `.env.local` 里写 `COACH_ALLOW_NO_ORIGIN=1`。

4. 在游戏里：菜单 → 设置，军师状态是「云端妙算」。

### 启动窗口里会出现的几种行

- `[coach] mode=live status=200 end=done in=412 cached=3610 out=188 ms=2317`：每个军师请求一行。`status` 是 HTTP 状态；`end=` 是这次回答怎么结束的（`done` 说完了，`tool` 军师要在棋盘上推演一步，`error:原因`，`aborted` 孩子已经走了下一步、不用说了）；`in / cached / out` 是输入、命中缓存的输入、输出的 token 数；`ms` 是耗时。请求在开始回答之前就被拒绝时是 `code=原因`，例如 `status=403 code=origin`、`status=429 code=rate`。这一行里只有数字和固定的词，没有棋局和对话的内容。
- `[api] 403: a request with a Host header "..." was refused ...`：有人用一个不是这台电脑的名字访问了军师服务，被拒绝了。见下一小节。
- `[api] 某个错误类名` 或 `[unhandledRejection] 某个错误类名`：服务器内部出了一次错，已经跳过，服务器继续运行。这里只打印错误的种类，不打印错误信息的原文（原文里可能带着 key）。

### 用别的名字打开时军师不说话

为了防止别的网站借孩子的浏览器偷用军师服务，`/api` 只在地址栏里的主机名确实是这台电脑时才回答：`localhost`、`127.0.0.1`、电脑名（`MY-PC` 或 `MY-PC.local`）、内网 IP（`192.168.x.x`、`10.x.x.x`、`172.16～31.x.x`、`169.254.x.x`）。**iPad 用电脑的内网 IP 或电脑名打开，不需要任何设置。**

如果你给这台电脑起了别的名字（比如路由器里配的 `chess.lan`，或者自己的域名），页面能打开，但是军师服务会拒绝：游戏里的设置显示「服务器拒绝了这个网址的请求（来源不被允许）」，启动窗口里出现上面那行 `[api] 403`。这时在 `.env.local` 里加一行，然后重新启动：

```text
COACH_ALLOWED_HOSTS=chess.lan
```

### 其它需要知道的

- 页面第一次询问军师状态时，服务器会在后台把大模型的 SDK 加载好（慢硬盘上要几秒），所以孩子的第一句讲解不会因为加载而超时。
- 军师服务不读取这台电脑上的 `OPENAI_ORG_ID`、`OPENAI_PROJECT_ID`、`OPENAI_LOG` 这几个环境变量。但如果电脑的环境里设置了 `OPENAI_CUSTOM_HEADERS`，SDK 仍然会把它加进发给网关的请求里：不需要的话请不要设置它。
- `COACH_TRUST_PROXY=1` 只在军师服务前面另架了反向代理时使用：这时限速按 `x-forwarded-for` 头的第一段来区分访问者。直接在家里用，不要打开它。

## 五、只有人能做的检查：真的 iPad

自动化测试跑的是电脑上的 Chromium 模拟出来的 iPad，不是真正的 Safari；声音也只验证了「不会爆音」，没有人用耳朵听过。到这份说明写成时，**真 iPad、真 Safari、用耳朵听声音，这三件事还没有人检查过**。请家长在孩子上手之前自己过一遍：

1. **Safari，横屏和竖屏各下几步**：试走、再点一次落点确认、换一步、悔棋、拆三个锦囊、点按钮问军师；接通了大模型的话再打字问一句（键盘弹出时，棋盘和输入框应当都看得见）。画面不应当有左右滚动条，也不应当上下滚动。
2. **从主屏幕图标进入**一次：全屏，没有地址栏，上次的棋局还在。
3. **五个要亲眼看的时刻**（这是整个游戏最想保住的感觉）：
   - 孩子自己**吃子**：先瞄准（棋子抬起、准星、虚线），确认后是从原位出发的完整动作；用炮吃子要有抛物线、一声炮响、短暂的停顿和震动。
   - **点了就动**：手指一碰棋子立刻抬起，包括打开页面后的第一下触碰；任何一步都不用等。
   - **先变脸，后说话**：试走之后，诸葛亮的表情和一句短短的语气词几乎同时出现，讲解的字随后才来；没有 key 时也一样。
   - **没人提醒的发现**：司马懿留了破绽，军师不出声，孩子自己找到了：印章、「主公英明！」和司马懿慌张的脸应当一起出现。
   - **亲手绝杀，输了不被数落**：将死时有停顿、倒下的老将、「绝杀！」、鼓声和彩纸；输了只有老将倒下、「惜败，再战！」和孩子本局最好一步的回放，不报失误的数目。
4. **用耳朵听**：关掉静音开关、调大音量；第一下触碰之后才有声音；落子、吃子、将军、锦囊、胜负各有各的声音；背景音乐不盖过音效，局面紧张时不变得刺耳；最大音量下没有破音；游戏里的静音按钮管用。
5. **第一下触碰的读数**：在 iPad 上打开 `http://<电脑的局域网地址>:5173/dev/audio.html`，点一下页面，日志里会出现一行

   ```text
   首次触碰  unlock() N 毫秒 · 其中建上下文 C · 预制音效 M 毫秒后就绪
   ```

   请记下 N、C、M 三个数。**N 减 C** 是第一下触碰里游戏自己占用的时间，开发机上约 10 毫秒，设计目标是不超过一帧（约 16 毫秒）；C 是浏览器建立声音设备的时间，游戏改变不了。如果 iPad 上 N 减 C 明显更大（比如超过 50 毫秒），第一下点击会发闷，请把三个数反馈给开发者。
6. **存档**：菜单 → 设置 →「导出存档」能下载到文件；再「导入存档」能读回来。
7. （可选，需要一台 Mac 接上 Safari 的网页检查器）打开 `http://<电脑的局域网地址>:5173/?test=1`，在控制台里输入 `window.__yijian.tasks.stats()`，其中 `speedClass` 应当是 `fast` 或 `mid`。是 `slow` 说明这台 iPad 算棋偏慢，军师的表情和讲解会来得晚。

## 六、已知的限制

教学对手（司马懿）：

- 对「刚学会走子」、比目标年龄段更弱的孩子，司马懿仍然偏强：模拟对局里，最弱的一档不看军师时第一盘只得一到两成分，听军师的话（落子前被拦一下明显丢子的棋）能到四成五到五成多。防止孩子一头撞进杀棋的，主要是诸葛亮在试走时的提醒。
- 他「像人一样会漏看」是有意保留的：低水平时大约每两盘会有一次因为漏看而丢一个车；刚吃了他的车的那个子，他偶尔也会忘了吃回；同一个送到嘴边的子连续三步不吃，在 1664 盘模拟里出现过 18 盘。
- 他在哪种设备上都按自己的水平算棋：对 5 级以下的孩子，快的 iPad 和慢的 iPad 上是同一个司马懿，只是快的回应得早；5 级以上，快设备上的他仍然略强一点。
- 势均力敌时一盘棋可能比较长：模拟里听军师话的孩子，一盘的中位数是 48 到 71 个回合。
- 一盘棋下过第 60 回合，司马懿会像下累了的人：局面相当时他偶尔失误一次，丢一个士、象、马或炮（不会白送车，也不会自己走进杀棋），失误之后先稳稳地走两步；孩子明显领先了，他才让孩子亲手赢下来。孩子落后很多时，从第 80 回合起他不再手软，把赢棋下完。即便这样，模拟里仍有 7% 到 8% 的对局孩子要走满 100 步（最强的一档孩子大约五盘里有一盘）：多半是谁也赢不了的残局（一车对一车、一炮对一炮、单兵对士象全），最后靠「六十回合不吃子判和」结束。司马懿还不会主动提和，孩子领先很多却赢不下来时他也不会认输，这两件事留给以后的版本。

军师（诸葛亮）：

- 「有更好的吗？」里给出的更好着法，它的好处是用简化的办法推出来的，说不出这几种：牵制、弃子、带将军的捉双、两步以上的杀棋威胁、将军之后开出的车路。
- 大约 1% 的失误，军师说不出具体毛病在哪，只能说这步不好。
- 军师提到几步之前的某一着时，那一着不一定能点开在棋盘上演示（只登记了孩子上一步以来的着法）。
- 军师对司马懿的着法开口讲解的次数比设计的预算多：设计是不超过四成，照脚本下的 30 手对局里（模拟回复，9 局）量到的是四成到将近六成（`npm run coach:bench` 会把它标成「超预算」）。没人问就说的总字数在预算之内（每局 770 到 990 字，上限 1200）。

界面：

- 窗口没有多余宽度时，棋盘和军师一栏之间只有 16 像素的间隔。
- 横屏窗口宽 900 到 943 像素时，军师的对话气泡会矮一些。
- 横屏、宽度不到约 620 像素的手机上，羽扇的动作有 1.2 秒会伸出窗口。
- 顶部有安全区（刘海）且宽度小于约 1130 像素时，棋盘偏离中心 8 像素。
- 「沙场」主题两侧铆钉的边距很紧；「隆中」主题的背景音乐比设计值响 0.5 到 0.8 分贝。

其它：

- 没有语音输入；朗读（念出军师的话）默认关闭，可以在设置里打开。
- 没有双人对战，也不能选难度：强弱由司马懿自己跟着孩子调整。
- 浏览器启动不了算棋的 Worker 时不能下棋（见「浏览器要求」）。

## 七、在线版本（GitHub Pages）没有军师服务

把仓库推送到 GitHub 的 `main` 分支后，会自动发布一个在线版本，地址是 https://gnailegoac.github.io/yijian-xiangqi/ 。GitHub Pages 只能放静态文件，放不了带 key 的代理，所以在线版本**没有军师服务，由本地军师讲解**：试走点评、三个锦囊、按钮提问、终局小结都照常有，只是没有打字提问的输入框。棋力、教学对手和存档与家里的版本完全一样。

如果以后把军师服务单独部署到一个 `https` 地址，在仓库的 Actions 变量里设置 `COACH_API_BASE`，在线版本就会去连它；不设置就是没有。

- iPad：iPadOS / Safari **16.4 或更高**。
- 电脑和安卓：Chrome **111 或更高**（同代的 Edge 也可以）。

npm test              # 只跑单元测试（Node 自带的测试框架，不需要浏览器、网络和 key）
npm run typecheck     # 只跑类型检查
npm run test:slow     # 耗时较长的引擎测试（perft、大量对局的对拍）
npm run test:e2e      # 浏览器端到端测试（Playwright + 模拟军师）

- `npm run test:sim` 和 `npm run bench` 只用本机算力，不联网。
- 通过 npm 给脚本传参数时要多写一个 `--`，例如 `npm run test:sim -- --games 8`。

## `npm run test:sim`：司马懿让得合不合适

它回答一个问题：对每一种水平的孩子，司马懿能不能把棋保持在「孩子赢得了」的范围里，同时不让人看出他在放水？做法是让四个模拟的孩子（A 到 D，从很弱到较强，都执红）和司马懿下完整的对局，然后数数。

```powershell
npm run test:sim                         # 完整的一轮：每组 64 局，17 组共 1088 局，10 到 15 分钟（5 个工作线程）
npm run test:sim -- --games 8            # 快速看一眼：每组 8 局，只算带 † 的线
npm run test:sim -- --only matched-B     # 只下某一组（也可以写 matched、coached、weak 这样的一类；weak 约 3 分钟）
npm run test:sim -- --path fast          # 换成一台快设备上的司马懿（还有 slow、table；默认 mid）
npm run test:sim -- --print 目录         # 把每一局的棋谱写到这个目录里，方便人读
npm run test:sim -- --json 文件          # 把全部数字写成 JSON；--jobs n 可以改工作线程数
```

同一个 `--seed`（默认 1）在任何机器上给出同样的数字。

**表格的每一行是一组对局：**

| 行 | 意思 |
|---|---|
| `plain-A` … `plain-D` | 不让棋的普通引擎。这是对照组：它应当把孩子压得很低 |
| `matched-A` … `matched-D` | 司马懿，水平定在这个孩子自己的档位上；孩子已经下过五盘 |
| `coached-A` … `coached-D` | 同上，并且诸葛亮会拦住丢 300 分以上的棋：十次里孩子有七次会重新想 |
| `high-A` | 司马懿一开始比最弱的孩子高 3.5 档：看他会不会自己降下来 |
| `first-A`、`first-B` | 孩子平生第一盘（不看军师）；`firstc-A`、`firstc-B` 是第一盘并且听军师的 |

**每一列：**

| 列 | 意思 |
|---|---|
| 局数、胜/和/负、得分 | 都是孩子一方的；得分 =（胜 + 和的一半）÷ 局数 |
| 平均局面 | 孩子每一回合所处局面的平均值，100 约等于一个兵；正数是孩子占优 |
| ±300内 | 孩子的回合里，局面在正负 300 分以内（胜负未定）的比例 |
| drift | 一盘结束时，司马懿比开局时调高或调低了多少档；负数是他让得更多了 |
| 步数 | 孩子一盘走的回合数（中位数） |
| 首吃 | 孩子第一次吃子发生在第几个半回合（中位数）；`-` 是一盘都没吃到子 |
| 绝杀/胜 | 孩子赢的棋里，有多少是孩子亲手将死的 |
| 长局 | 拖到 100 回合以上的对局比例 |
| 放杀/局、让子/局、漏看/局 | 每盘里司马懿放过杀棋、有意留机会或让步、「漏看」的次数 |
| 深度 | 司马懿选定的那一着平均算了多深 |

**表格下面是一条条「线」**，每条开头是结论：`通过`、`未达标`、`只打印`（只是给人看的数，没有线）、`不计`（局数太少，这条线这次不算）、`无数据`。带 † 的线在快速看一眼时也算，其余的线只在每组下满 64 局时才算。线的内容：

- 普通引擎（`plain`）：平均局面要低于 −400。
- 水平对等（`matched`）：B、C、D 的平均局面在 −150 到 +350 之间，A 不低于 −450；±300 以内的回合，A 不少于 45%、B 50%、C 和 D 60%。
- 听军师的孩子（`coached`）：得分 B、C、D 不少于 0.40，A 不少于 0.30；步数的中位数不超过 85。
- `high-A`：终局时 drift 不高于 −1.5（他确实降下来了）。†
- 第一盘：`firstc-B` 不少于 60%，`first-B` 不少于 30%，`firstc-A` 不少于 45%，`first-A` 只打印；孩子第一次吃子的中位数不晚于第 14 个半回合（†）。
- 孩子赢的棋里至少一半是亲手将死的。†
- 「不像放水」的五条：(h) 没有一盘连续两步放过一步杀（†）；(i) 同一个子连续三次不吃的对局不超过 2%；(j) 没有一次让出 500 分以上，也没有白送一个车（†）；(k) 该吃回的车没吃回不超过 1%；(l) 领先 600 分以上时走回头路的着法不超过 4%。
- 长局：孩子走满 100 步的对局，在全部教学对局里不超过 10%，在最多的那一组里不超过 33%。这两条是防止退步的护栏，不是目标：没有收尾规则时是 12% 到 15% 和 31% 到 41%，现在是 6% 到 8% 和两成上下。

退出码：0 是该算的线全部达标；1 是有线未达标、有对局没下完或结果文件没写成；2 是参数写错了（包括写不进去的输出路径，开局前就会检查）。

怎么读：先看有没有 `未达标`。贴着线的数字不要只看通过与否：每组 64 局时，得分这类比例换一组种子（`--seed 1001`）会有几个百分点的出入，所以一条线差一点没过，先换一组种子再看一次，两次都不过才是真的问题。`--path` 可以换司马懿算棋的方式：`mid` 是默认，是对局本身的算法配一台中速设备的虚拟时钟；`fast`、`slow` 是更快、更慢的设备；`table` 是最快的定深算法，约 5 分钟。司马懿按自己的水平决定算多深，不按设备：5 级以下三种设备下出来的是同一盘棋，5 级以上快的设备上他仍然略强一点，所以发布前最好把 `--path fast` 也跑一遍（约 15 到 20 分钟）。这些数字和机器快慢、当时忙不忙无关。这个模拟只检查司马懿，不改他：线不过时要改的是 `src/core/teacher.js`，那是另一件需要决定的事。

## `npm run coach:bench`：大模型军师的验收

它对着**正在运行的**军师服务量三件事：快不快、短不短、说的着法在棋盘上有没有依据。

```powershell
# 窗口一：启动军师服务（.env.local 里有 key，窗口里显示“军师模式：live”）
npm start
# 窗口二：
npm run coach:bench
```

它做两部分，各 5 次：

1. **回放请求样本**：把 `tests/fixtures/coach/` 里军师服务能接受的 11 个请求各发一遍（另外 2 个是「工具续问」的中间一段，带着只对模拟密钥有效的令牌，不回放）。
2. **照脚本下 30 手**：用游戏自己的对局模块（只是界面换成一个只做记录的）和司马懿下 30 手。孩子照脚本行事：大部分时候试走一步好棋、等军师点评、确认；第 4、9、14… 手先试一步会丢子的棋，看军师怎么拦，再换一步；第 7、22 手拆三个锦囊；另有十几处点按钮提问，第 16 手打字问一步棋。提前终局就接着下一盘，30 手走完后认输，所以每一局都有一句终局的话。

打印的内容：每一类事件（开局、对手着法、试走点评、锦囊、提问、终局）的 `open`、首字、`done` 三个时间的中位数和九成位数（毫秒），token 用量和缓存占比，超过提示字数和显示上限的回复数，对不上棋盘的着法数；每一局里「没人问就说」的字数；最后是一条条验收线。

**不达标就失败（退出码 1）的线：**

- 回复里的【着法】全部有依据（对局里：能在棋盘上走通；请求样本没有棋盘：必须是军情里出现过的着法）。
- 没有一条回复超过显示上限（提示字数的 1.5 倍）；超过提示字数的不超过两成。
- 没有禁用词（白赚、稳赚、必胜、引擎、程序、分数、离线、主帅、又是、总是、老是）。
- 每一局里没人问就说的字数（着法字幕、讲对手、试走点评和提醒、终局的话，连同开口的语气词）不超过 1200。
- 首字时间的中位数：对手着法和试走点评不超过 2.0 秒，提问和锦囊不超过 3.5 秒。（页面等到这个时间就改用本地军师的话；对局里等不到的次数会计入这个中位数并单独标出。）
- 重复发同一个请求时用上了缓存（网关根本不报告缓存 token 时这一条不算）。
- 每次问答、每一局都走完了，对局模块没有报错。

「司马懿的着法里军师开口讲解的比例不超过四成」是设计预算，超出时标成 `超预算`，不影响退出码：它取决于游戏自己「什么时候开口」的规则，不取决于大模型。退出码 2 表示参数写错了，或者连不上军师服务。

需要知道的：

- **时间和费用**：完整的一轮大约 350 到 400 个请求（用模拟回复量到的是 356 个）。为了不撞上每分钟 30 次的限速，每个请求占 2.1 秒，估计要半小时上下（这是按请求数估的，完整的一轮对着真网关还没有人跑过）。先看一眼可以用 `npm run coach:bench -- --runs 1`：两部分各 1 次，约 60 个请求，三分半钟。
- **对着真网关量到过什么**（`--runs 1`，默认模型）：各条线全部达标；首字时间的中位数，讲对手 1.0 秒、试走点评 1.2 秒、锦囊 1.3 秒、提问 1.4 秒。但网关的延迟是两头分布的：大约四分之一的请求要 3.5 秒以上才出第一个字，这些试走点评和讲对手的话，页面等满 2 秒就改由本地军师说了（那一局里 21 次试走点评有 6 次、12 次讲对手有 3 次）。把等待放长到 3 秒几乎救不回来，所以 2 秒的上限没有改。
- **每天的上限**：每个地址每天 600 次，所以同一天（UTC）里跑第二遍会被限速（报告里出现 `http:429`）。要多跑，在 `.env.local` 里临时调大 `COACH_IP_DAILY`、`COACH_GLOBAL_DAILY`；限速也一起调大后可以加 `--pace 0`。
- **不花钱先试工具**：窗口一改成 `npm run start:mock`。模拟回复只能说明这个工具和对局流程是通的，报告里会写明「不算验收」。
- 其它参数：`--base <地址>`（默认 `http://127.0.0.1:5173/api`）、`--moves <手数>`、`--seed <数>`、`--only fixtures|game`、`--json <文件>`（把原始数据写出来）。

## 构建和部署

```powershell
npm run build
```

生成 `dist/`：

- `src/` 和 `styles/` 被复制到 `dist/a/<构建号>/` 下，`index.html` 里的引用同时改写过去。每次发布的构建号不同，浏览器缓存里的新旧模块不会混用。
- `dist/icons/` 里的三个图标（主屏幕图标和清单图标）由 `scripts/make-icons.js` 直接画出来，不依赖图片库。
- `dist/config.json` 写明这一版有没有军师服务（默认没有）。放在别的静态主机上时如果缺了这个文件，页面只是在控制台里记一条 404，照样由本地军师讲解。
- 构建同时是一次检查，任何一项不过都会失败，并且不留下 `dist/`：模块之间的引用规则、引用的文件是否都存在、有没有用到老 iPad 不支持或需要 https 的接口、页面加载的每个文件是否都在 `dist/` 里、`dist/` 里有没有混进 `server/`、`scripts/`、`tests/`、`dev/`、`.env*`。
- **密钥检查**：`dist/` 的任何文件里出现 `COACH_API_KEY` 这个名字、形如 `sk-` 开头的 key、或者某个密钥的**值**，构建就失败。「值」来自两处：构建时环境里名字以 `_KEY`、`_TOKEN`、`_SECRET` 结尾的变量，以及项目文件夹里 `.env`、`.env.local` 中的 `COACH_API_KEY` 和 `COACH_SIGNING_KEY`（8 个字符以上）。所以不小心把 key 粘进了 `src/`，在自己电脑上构建时就会被拦下。失败信息只说是哪个文件、哪个变量，不会把值打印出来。

在本机检查构建结果：

```powershell
node scripts/serve.js --dist --port 5174
```

推送到 `main` 后，GitHub Actions（`.github/workflows/deploy.yml`）依次做三件事：`check`（类型检查、全部单元测试、构建）、`e2e`（Playwright 浏览器测试），两者都通过后 `deploy` 重新构建并发布到 GitHub Pages。

## `scripts/serve.js` 的参数

```text
node scripts/serve.js [--port 5173] [--host 127.0.0.1] [--dist] [--mock] [--api-only]
```

| 参数 | 作用 |
|---|---|
| `--port` | 端口，默认 5173 |
| `--host` | 监听地址，默认 `127.0.0.1`（只有本机）；`0.0.0.0` 让局域网里的设备也能访问 |
| `--dist` | 不读源码，改为提供 `npm run build` 生成的 `dist/` |
| `--mock` | 军师用固定的模拟回复，不访问大模型（测试用，等价于 `npm run start:mock`） |
| `--api-only` | 只提供 `/api`（军师服务），不提供页面 |

这个服务器只提供白名单里的文件：`index.html`、`favicon.svg`、`manifest.webmanifest`，以及 `src/`、`styles/`、`dev/` 三个目录里扩展名为 `.html .js .css .svg .json .webmanifest .png .txt` 的文件。其余一律 404，包括 `.env.local`、`.git`、`server/`、`scripts/`、`tests/`、`node_modules/`、`package.json`。`/api` 另外只在 Host 头是这台电脑的名字或地址时才回答（见第四节）。

## 目录

- `index.html`、`manifest.webmanifest`、`favicon.svg`、`styles/`：页面外壳和样式。
- `src/core/`：规则引擎、记谱、搜索（Worker）、棋局事实、教学对手。
- `src/coach/`：交给军师的事实包、本地军师的句子、和军师服务对话的客户端。
- `src/game/`：对局状态机、任务与取消、存档、导演（决定什么时候讲什么）。
- `src/ui/`：棋盘、特效、音效、诸葛亮和司马懿、对话区、按钮与弹层。
- `src/app.js`、`src/config.js`：装配入口和 `config.json` 的读取。
- `server/`：军师服务（校验、限流、签名、提示词、调用网关）。只在电脑上运行，不会进入 `dist/`。
- `scripts/serve.js`：本地服务器（白名单静态文件 + `/config.json` + `/icons` + `/api`）。
- `scripts/build.js`、`scripts/make-icons.js`：静态构建和图标。
- `scripts/sim.js`、`scripts/coach-bench.js`、`scripts/bench.js`：上面说的三个量具。
- `tests/unit/`、`tests/slow/`、`tests/e2e/`：单元测试、慢测试、浏览器测试；`tests/fixtures/`：请求样本和存档样本。
- `dev/`：各个界面部件的独立调试页，只在 `npm start`（不带 `--dist`）时能访问，不会进入 `dist/`。
- `docs/design/`：这次重构的设计合同和各轮记录的备份，不参与构建。
